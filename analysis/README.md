# Data Analysis

## Intended responsibilities; not implemented

Analysis tooling will validate measurement completeness, load immutable run data/metadata,
compute distributions and statistical summaries, compare environments, and generate
reproducible tables/figures. `mt analyze` will integrate these tools; an analysis language
and concrete statistical libraries are not selected here.

Report latency distributions (likely p50/p95/p99), achieved/sustainable throughput,
CPU cost, memory cost, active-readiness startup, and defined scalability measurements.
Distinguish process/runtime/container memory from total environment cost, especially for
VMs. Throughput / CPU usage is a candidate efficiency metric requiring consistent units.

## Reproducibility and integrity

Raw results, logs, and metadata must remain unchanged. Write derived output separately
(e.g. `experiments/processed/` and `experiments/figures/`, not created yet). Every
measurement-based figure/table must be generated by scripts and traceable to run IDs,
source commit, resolved scenarios, versions, and analysis configuration.

Validate failed/incomplete runs rather than silently discarding them. Implement and
document cleaning, filtering, aggregation, and outlier handling; retain original data.
Use effect sizes, confidence intervals, and practical significance. Exact tests, thresholds,
exclusions, and final repetition count must follow pilot distributions and be specified
before final campaigns. Approximately 30 repetitions is proposed, not a statistical rule.
H1–H3 remain hypotheses. See [research.md](../docs/research.md) and
[methodology.md](../docs/methodology.md). No analysis implementation is introduced yet.
